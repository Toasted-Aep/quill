## Standing rulings the user still owes

- **COPIC seam** — RV42, RV69, RV99, G40, G82 carry almost all of it. A hand-extension, not a re-sourcing.
- **Pen colour in the pen icon** — 48 of 72 pen/paper pairs under 3:1, worst 1.01:1. Live behind `ToolWheel.PenColourInIcon`; needs an outline or a non-page-derived base.
- **Blueprint / Brown Paper dial seats** — excluded from §29's floor because the gate is on L\* not on ratio. Verified to read as clear discs, but if they ever read as absent that gate is a ruling.
- **§28.4's WinUI hover-wash** on `BottomMenu` — WinUI's own plate, not ours.
- **The Mouse Mode row is inert while Touch draw is on and the Pen tool is up** (run 22, §45.4). `HandleMousePress` is reached only down the `!HandDrawMode` branch, so with 6.1's ruling applied **all four** Mouse Modes — Normal, Grab, Select, Move — stop dispatching for the mouse, not just Select. The user accepted "a mouse drag will now ink where it previously selected"; what was not put to them is that the whole row, and its caption *"What a mouse drag does on the page. The pen is unaffected by this."*, now describes nothing while the pen is the active tool. Either the row is disabled with a reason (the Finger Action row's own shown-but-disabled pattern), or Touch draw is scoped so the modes still reach. **Not guessed at in run 22 — it is a ruling.**
- **The Touch draw caption contradicts the shipped default** (run 22, §45.5). The caption reads *"Off is the pen-first default — your palm and your fingers move the page, and only the pen leaves ink."*, but `Library.FingerAction` defaults to `"UseActiveTool"` (`NoteModels.cs:863`), so with 6.1 applied the shipped default is **on**. One of the two is wrong; which one is the user's call, not a code question.
